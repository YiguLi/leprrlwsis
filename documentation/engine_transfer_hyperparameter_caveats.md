# 换引擎（WFSim → FLORIS）时 `td3per` 的超参数可迁移性

**问题**：若在 FLORIS 上找到各类最佳超参数，这些超参数对 WFSim 是否也是较优的？

**结论：分两类，不能整体断言"是"。**

- **算法类超参数**（网络结构、actor/critic 学习率、bsize、τ、policy_delay/noise/clip、
  PER 三项、乘性对偶步长）—— 可迁移。它们在**归一化空间**里工作，或公式本身对尺度免疫。
- **与引擎耦合的超参数/常量**（`c1` 的 3 MW 限值、`K_V`、`d_block`、两通道 `scale`、
  观测归一化除数、动作先验带、`--discount`/`--window_length`、探索噪声振幅）——
  **不可直接迁移**，其中一部分必须显式重标定。

> ### ⚠ 口径更正（2026-10-05，后续工作追加，原分析未改动）
>
> 本文 §2 表格里的电平比 **1.74×**（以及由它派生的 `COST_SCALE_TD3 → 331`、`VALUE_SCALE`、
> `obs[3]/10` 除数等"×1.74"建议）来自 **FLORIS 随包默认尾流参数（stock）** 这一**非生产**口径。
> `agentutil/probe_u10_engine_forms.py` 的裁决（硬判据：路径 A 逐位复现
> `clip_check_fullrange.json`，`max|Δ| = 0.000e+00`）：u=10 同一批行为上
> **stock `1.7164`** vs **生产（`calibrated=True`）`0.9892`**。
>
> ⇒ **生产口径下这些"×1.74"整体系数不应再被使用**；`obs[3]` 的分布右移量、
> `VALUE_SCALE` 的尺度红利都要按 `calibrated` 口径重算。
> ⚠ 但 **`COST_SCALE_TD3` 的 ×3.31 不是纯电平比**（它是 `c1` 块和越限率的松紧比，
> 与动作分布和阈值耦合），本文未重算 ⇒ 该行只作"**需按生产口径重做**"标记，
> 不能反向断定 331 是错的。详见 `documentation/engine_u10_three_forms.md` §0。


下面给出**实测依据**。数据来自 `output/engine_minute_compare.json`（单排 5 台 5D、
`a≡0.3333`、`γ≡0`、风速 = `FFC_speed_noise_1.csv` 第 1 日列前 100 min、均值 7.524 m/s），
分析脚本 `agentutil/analyse_engine_cost_scale.py`（口径取自 `hsrl_cost.py` 单一真源）。

---

## 1. 决定性实测：同一套 `td3per` 口径放在两个引擎上，约束松紧差了 **3.31×**

`hsrl_cost.py` 的 H 层口径（逐字）：
`P_F = |P_G(t) − P_G(t−1)|` [MW]，`c1 = P_F + K_V·(P_F−3)⁺`（`K_V=20`）[MW·step]，
块预算 `d_block = D_BLOCK = 3 MW × 5 步 = 15` [MW·step]。

| 指标 | WFSim | FLORIS | 比 |
|---|---|---|---|
| 平均出力 [MW] | 1.5622 | 2.7205 | 1.7415 |
| `P_F` 均值 | 0.6880 | 1.1864 | **1.7244** |
| `P_F` p95 | 1.9200 | 3.3110 | 1.7245 |
| `P_F` max | 3.5575 | 6.1491 | 1.7285 |
| **越限 `P_F>3` 步数占比** | **1.00%** | **8.00%** | **×8.00** |
| `c1` 均值 [MW·step] | 0.7995 | 2.6466 | **3.3102** |
| 块和 `Σ₅c1` 均值 | 3.9976 | 13.2328 | **3.3102** |
| 块和 / 预算 `d_block=15` | 0.2665 | **0.8822** | — |
| **超预算块占比** | **5.0%** | **25.0%** | ×5.0 |

**反事实对照**：把 FLORIS 的电平整体 ÷1.7414（模拟"重标定过的臂"）后重算同一口径：

| | 重标定后 | WFSim |
|---|---|---|
| 越限率 | **1.0000%** | 1.0000% |
| 块和 / 预算 | **0.2625** | 0.2665 |

⇒ **3.31× 完全来自"电平 × 绝对阈值"的错配，不是噪声、也不是分辨率差异。**

### 为什么是 3.31× 而不是 1.74×（放大机制）

两个绝对量（3 MW 限值、`d_block=15`）本身**不随引擎缩放**，而 `P_F` 随电平线性放大：

1. 硬限 `P_F > 3`：`P_F` 的分布整体右移 1.72× ⇒ **越限频率 ×8**（阈值在分布尾部，非线性放大）；
2. 软罚 `K_V·(P_F−3)⁺`：频率 ×8 **叠加**超出量的增加 ⇒ `c1` 均值 **×3.31**。

**这是绝对阈值最危险的放大方式**——阈值越靠分布尾部，跨越率对电平的敏感度越高。

## 2. 哪些超参数必须显式重标定

| 超参数 | 位置 | 为什么不行 | 建议 |
|---|---|---|---|
| `COST_SCALE_TD3 = 100` | `hsrl_cost.py:63` | 定标时 cost 块奖励 ≈0.04；FLORIS 下 **0.1323**（×3.31），两通道"块奖励同量级"失衡 | ≈ **331**（= 100×3.31） |
| `VALUE_SCALE = 1000` | `hsrl_cost.py:57` | 同理，r1 也 ×1.74；利润通道虽被 scale 归一，但"尺度/条件数"红利是相对该 scale 定的 | ≈ 1000×1.74 |
| `Normalize` 的 `obs[3]/10` | `td3per_myfunc.py:458` | **`obs[3]` = `PowerOutput(u, a)`（引擎出力）**，FLORIS 下大 1.74× ⇒ 同一维在 [0,1] 里的分布整体右移 | 除数 ×1.74 |
| `--discount 0.98` / `--window_length 1` | `td3per_main.py:886/940` | 两者都与"有效 horizon / 记忆需求"绑定。⚠ **原写的"FLORIS 无输运延迟、WFSim 有输运延迟"已证伪**（`documentation/engine_u10_three_forms.md` §3：`WFSim_port` 每次调用重置流场为均匀流、只积分 5 s ⇒ 调用间**无状态**，跨调用滞后不可能存在；输运尺度 5D/u=50 s、全场 200 s 被跳过）⇒ **两引擎在当前耦合下都是无记忆映射**，"记忆需求不同"这条理由**不成立** | ~~WFSim 侧可能受益于 `window_length>1`~~ ⇒ 该条不再构成迁移差异；`--discount` 仍可按"有效 horizon"独立调 |
| 动作先验带 `WT_LO/WT_HI = 0.05/0.45` | `hsrl_warmup.py:60` | 两引擎的 `Cp(a)`/`CT(a)` 关系不同（WFSim `CT_prime=4a(1−a)²` vs FLORIS `CT=4a(1−a)`）；且 myfunc 的 `CheckAction` 夹到 `[0,0.5]` | 需按各引擎重扫（本项目已实测 FLORIS 侧偏差点在 a≈0.40） |
| 探索噪声振幅（`wt_noise`/`sig_noise_*`、`policy_noise`） | `td3per_main.py:1035-1039` | 噪声是"动作空间里的距离"，而同一动作在两引擎的**物理后果**差 1.87×（尾流深度比） | 需按引擎调 |

**为什么 `s_c` 的方向是"必须调"而不是"调了更好"**：`model.py` 的 `Critic` 输出层
`init_w=3e-3`，`hsrl_cost.py` 的注释记录了代价：`c̄/s_c` 落到 O(0.004) 时
**cost critic 会塌成常数（run9: Q_c ≡ 360 且 ∂Q_c/∂a ≡ 0）**。FLORIS 把 `c̄` 抬到
0.1323 属反方向失衡，同样会破坏"两通道值平衡"这一被显式设计过的机制。

## 3. 哪些超参数确实可以迁移

| 项 | 为什么免疫 |
|---|---|
| `hidden1/hidden2`、`lr`、`prate`、`bsize`、`tau`、`policy_delay/noise/clip` | 在归一化空间工作；引擎只改数据分布，不改"网络该多大" |
| `PER_alpha/beta/epsilon`、`beta_increment_per_sampling` | 优先级 `\|TD_p\|/mean_p + \|TD_c\|/mean_c + ε` 是**自归一化比值**（`hsrl_cost.py` 明确论证对 scale 免疫） |
| `hc.dual_update`（乘性对偶）、`ETA_LAM` | 对 `EMA/d_block` 的**比值**更新，对尺度免疫 |
| `λ` 区间 | `h_settings()` 用 `lam_scale()=s_c/s_p` 自动重标，**物理价恒为 λ_raw** ⇒ 改 scale 不会静默改变约束松紧 |

⚠ 但"可迁移"≠"最佳"。TD3 是近似算法，策略质量取决于 **critic 拟合精度**。两引擎的
Q 函数不同（尾流亏损深 1.87× ⇒ 维间耦合更强），同一结构在两边逼近误差不同 ⇒
**即使最优超参数完全相同，最优策略也未必相同**。

## 4. 可执行建议：在 FLORIS 上调参前先做"口径标准化"

```python
import hsrl_cost as hc
# 1) 量出两引擎的三条比（用同一 --steps 100 测，脚本见下）
#    k_level = E_floris / E_wfsim          ≈ 1.74
#    k_cost  = c̄_floris / c̄_wfsim          ≈ 3.31   ← 不是 1.74
#    k_obs   = (obs[3] 的均值比)            ≈ 1.74
# 2) 显式设定，让"物理约束语义"在两引擎一致
hc.set_value_scale(1000.0 * k_level)
hc.set_cost_scale(hc.COST_SCALE_TD3 * k_cost)
# 3) 观测归一化除数按 k_obs 调整（td3per_myfunc.Normalize）
# 4) 验收判据：调参前后比较
#    越限率 / 块和÷预算 / 超预算块占比  三个数应对齐
```

**验收自查**（标准化的唯一硬判据）：重标定后应能复现
`越限率 ≈ 1.0000%`、`块和÷预算 ≈ 0.263`（即 WFSim 的口径）；
本报告的实测已证明这一步是可达的（÷1.7414 后精确回到 1.0000% / 0.2625）。

---

## 5. 局限

1. 只测 **100 分钟、1 个日场景、`a≡0.3333`、u 均值 7.52 m/s** ⇒ 3.31× 会随风速/动作改变，
   必须按上式现测（脚本已给）。
2. **额定区以上（u>10.4 m/s）没测**。本项目表无量定上限，高风速下两边 `u³` 行为可能不同。
3. **`a` 变化时的比值没测**。两引擎的 `CT(a)` 关系不同，动作带上 3.31× 可能不是常数。
4. 本节只做**超参数可迁移性**的判定与实测，**不含**任何"哪套超参数更优"的评价。
