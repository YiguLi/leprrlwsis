# aifflor 线性行为分支（`--lin_wt`）

> 一句话：**actor 只决定首尾两台的动作 `a0` / `a4`，中间三台由线性插值得到并保留两位小数**；
> 其余（HSRL 语义、奖励/成本、critic、探索、warmup、日志）一律不动。
>
> 开关：`--lin_wt 1`（默认 0）；小数位：`--lin_wt_decimals 2`（默认 2）。
> 契约测试：`python agentutil/test_aifflor_lin_wt.py`。

---

## 1. 动作定义

前 5 维风机动作（第 6 维 `g` 原样保留）：

```
a0 = actor[0]                       （首端，原样，不取整）
a4 = actor[4]                       （末端，原样，不取整）
a_i = round(a0 + (a4 − a0) · i/4, 2)     i = 1, 2, 3
```

例：`a0 = 0.12, a4 = 0.25` ⇒ `[0.12, 0.15, 0.19, 0.22, 0.25]`。

* **有效自由度 = 2**；actor 的第 1..3 维输出**存在但无用**（投影只读第 0/4 维
  ⇒ 对它们的梯度恒为 `0`，不是"很小"）。
* 首尾维**不取整、不 clip**：越界仍由 `check_action_H_hsrl` / `CheckAction`
  裁剪并计 `pen5`。因此首尾越界时，由它们推出来的中间维可能同时越界，
  `pen5` 按实际越界维数累计。
* 第 6 维（HSRL 的块总放电量 `g`）**完全独立**。

### 1.1 中间三台有没有"actor 行为 / 梯度"？

**没有独立的 actor 行为，也没有独立的 actor 梯度。**

* 中间三台的轴向因子是 `a0/a4` 的**确定性函数**，不是网络输出；
* 实现上 actor 仍保留 6 个输出单元（`nb_actions=6`），这是为了**不改** critic 的
  6 维动作输入、checkpoint 形状、warmup/日志口径；`proj_lin_wt` 在 forward 里把
  第 1..3 维**覆盖**掉；
* 因此对 raw 动作的第 1..3 维有 `∂Q/∂a_j ≡ 0`（它们不是自由变量），契约测试
  正是在钉这一点；
* 中间动作对 Q 的影响不会消失：它通过 `∂a_i/∂a0 = 1−i/4`、
  `∂a_i/∂a4 = i/4` 回到端点，进入 actor 对 `a0/a4` 的梯度。actor 学的是
  "端点如何改变整条型线"，不是"中间三台各自的动作"。

> 若要求网络输出层本身只有 `a0/a4/g` 三个神经元，需要改 actor 输出维数
> （参数量/checkpoint 形状随之改变），这与"其他不变"冲突；当前实现选择
> "6 维输出 + 投影覆盖"，与 `--scalar_wt` 的既有做法一致。

## 2. 为什么是"首尾 + 线性插值"

`agentutil/probe_turbine_wake_attribution.py`（单排 5 台、FLORIS 真值）给出的
动作灵敏度结构：

| 机组 | 净 `∂P/∂a` | 自身项 / 下游耦合 | 真实 `∂c1_block/∂a` 符号稳定率 |
|---|---:|---|---:|
| T1（首端） | **+1.506** | 9.252 / −7.746（抵消 84%） | **84%** |
| T2 | −0.069 | 自身与耦合近抵消 | 43% |
| T3 | −0.034 | 耦合 **超过**自身 ⇒ 符号反 | 48% |
| T4 | −0.187 | — | — |
| T5（末端） | **+2.957** | 下游耦合恒 0 | **90%** |

⇒ 中间三台对"动作 → 波动成本"几乎是**近零/符号不可辨识方向**；两端才是稳定、
量级大的通道。线性行为分支把 5 维压成"两端 2 维 + 整排线性型线"：

1. 去掉中间三个近零方向，降低 actor 要辨识的维数；
2. 保留整排动作的**连贯形状**（不是 `--scalar_wt` 的"五台全相等"）；
3. 型线是 actor 输出的确定性函数 ⇒ critic 的动作输入仍在同一 6 维空间，
   不需要改网络结构。

## 3. 与现有动作流形开关的区别

| 开关 | 流形 | 有效自由度 | 中间维 |
|---|---|---:|---|
| 默认 | 5 维独立 | 5 | 自由 |
| `--farm_level 1` | `a_i = s·c_i`（`FARM_CENTRE`） | 1（+g） | 由射线决定，保留形状 |
| `--scalar_wt 1` | `a_i = a_0` | 1（+g） | 全部等于首端 |
| **`--lin_wt 1`** | **首尾 + 线性插值** | **2（+g）** | **线性型线，两位小数** |

三者**互斥**（`aifflor_main.py` 里 assert）：同时开会让"到底投影到哪条流形"
不可判读。

## 4. 实现落点（缺一处就会被绕过）

| 位置 | 作用 |
|---|---|
| `model.proj_lin_wt` / `proj_lin_wt_np` | 投影的唯一真源（torch / numpy 两版） |
| `model._round_half_away_ste` / `_round_half_away_np` | 四舍五入 + STE（见 §5） |
| `SP_TD3._project` | **所有 actor 前向**（`_act`、target actor、critic 的演员评估点） |
| `SP_TD3._project_np` + `select_action` | **加完探索噪声之后**的实际执行动作（否则噪声会把中间维打散） |
| `aifflor_main._apply_lin_wt` | warmup 调度 / `_diag_fix_action` / `--explore_mix_blocks` 之后、动作检查之前强制落回流形 |
| `train()`（旧口径） | warmup 与 actor 两条路径都调用 |
| `train_hsrl()`（`--hsrl`） | warmup 与 actor 两条路径都调用 |

**下层 BESS 不受影响**：L 层只有 1 维动作，`SP_TD3` 构造时自动把
`lin_wt` 置 `False`（`nb_actions < na_box`），否则会把 1 维动作误扩成 5 维。

## 5. 两位小数怎么落地：前向量化 + STE

需求是"中间三维保留两位小数"。若直接在投影里 `round`：

* 前向确实得到两位小数；
* 但 `round/floor` 的导数几乎处处为 0 ⇒ **中间维对 `a0/a4` 的梯度贡献被清零**，
  训练只能看到首尾维的"直接效应"，看不到"型线变化"的效应。

因此 `proj_lin_wt` 用 **straight-through estimator**：

```python
y = sign(x) * floor(|x| * 10^d + 0.5 + 1e-6) / 10^d
return x + (y - x).detach()          # 前向 = y，反向 = 1
```

* **前向**：actor 评估点、replay 动作、实际下发 env 的动作都是两位小数；
* **反向**：按连续线性插值传梯度 ⇒ `a0/a4` 仍可学；
* `1e-6`（缩放后 = 动作量 `1e-8`）只吸收 float32 在 `.xx5` 边界上的表示抖动
  （`0.12` 实际是 `0.1199999973…`），不改变正常四舍五入；
* 插值与取整中间量用 **float64** 计算再写回原 dtype ⇒ torch 与 numpy 对同一
  输入给出同一位小数。

> 取舍：量化使"动作 → 奖励"在 `0.01` 网格上分段常值。STE 是让梯度仍然可用的
> 标准做法；它**不改变执行的动作**，只改变反向传播的近似。

## 6. 训练期行为

* **探索**：噪声加在 6 维 actor 输出上，然后重新投影 ⇒ 只有首尾维的噪声有效，
  中间维仍由（带噪的）首尾决定；`g` 的噪声照旧。
* **warmup**：LHS / `unified` 调度产生的 5 维动作同样在 `_apply_lin_wt` 处
  落回流形 ⇒ replay 里没有流形外动作（与 `--scalar_wt` 同口径）。
* **两条主循环都接**：旧 `train()` 与 `train_hsrl()` 都在动作检查前调用；
  不开 `--lin_wt` 时该函数立即返回，旧路径逐位不变。
* **`--branch_*`（同块首宽动作覆盖）**：branch 的动作集是独立生成的，**不**经过
  线性投影（"其他不变"）。若同时开 `--branch_every`，critic 会同时看到流形外
  的 branch 动作与流形内的 actor 动作；只想验证线性分支时建议 `--branch_every 0`。

## 7. 已知局限（刻意保留）

1. **型线被强制为线性**：真实最优型线未必线性（`FARM_CENTRE` 就不线性）。
   这条分支测的是"两端 + 线性"这个结构假设，不是"最优型线"。
2. **只有 2 个自由度**：中间三台无法独立微调；若最优解需要非单调型线，这条臂
   会系统性吃亏。
3. **量化**：两位小数 ⇒ 中间维在带内是 51 级格点；首尾维仍连续。`--lin_wt_decimals`
   可改（`<0` 关闭取整），但改小数位会改变动作集，跨 run 不可直接比。
4. **首尾越界的连带罚**：首尾维越界会推出中间维越界，`pen5` 可能一次计 3~5 维；
   这是"用 2 维驱动 5 台"的必然结果，不是 bug。

---

## 8. 用法与验证

```powershell
# 线性行为分支（HSRL 口径）
python aifflor/aifflor_main.py --hsrl --lin_wt 1 --seed 0

# 短程冒烟
python aifflor/aifflor_main.py --hsrl --lin_wt 1 --max_steps 300

# 契约测试（只读；单点 FLORIS 求值，不跑 episode）
python agentutil/test_aifflor_lin_wt.py
```

契约测试覆盖：

* 投影语义（首尾原样、中间两位小数、`g` 不动、不 clip、幂等、`nt` 泛化）；
* 梯度（`∂/∂a1..a3 ≡ 0`，`∂/∂a0`、`∂/∂a4`、`∂/∂g` 非零；STE 前向取整/反向恒等）；
* agent 层（噪声之后仍在流形上、ε=0 的确定性输出、下层 1 维自动跳过）；
* 物理（同首尾、其余维任改 ⇒ 出力逐位相同；改 `a4` 出力变化）；
* 默认臂（`lin_wt=0` 时 `_project` / `_project_np` 严格恒等）；
* 接线（旧 `train()` 与 `train_hsrl()` 都调用 `_apply_lin_wt`，CLI 参数与互斥断言存在）。
