# 五步块整体 C1 critic：成本精度 + 行为梯度

## 任务

五步块总成本（`hsrl_cost.py` 的 c1 口径）：

```text
c1_t = PF_t + 20·max(0, PF_t − 3)
C1   = Σ_{t=0..4} c1_t
PF_0 = |P(u1,a) − P(u0,a)|
PF_t = |P(u_{t+1},a) − P(u_t,a)|,  t=1..4
```

- `PF_t` 是每个 `|ΔP|`；`PF_t>3 MW` 时额外乘 `K_V=20`（硬折点）；
- 动作：1D `a∈[0,0.5]`，五步块内恒定；
- 状态：
  - `useq`  = `u1..u5`（**严格块内五步**，缺 `u0`）；
  - `useq6` = `u0..u5`（多一个块前 `u0`，用于第一项）；
- 这两个都是**五步块内/块边界风速**，属于 hindsight/privileged 信息，只给 critic。

## 数据

复用 `data/aifflor_ua_f5_scalar.npz`（40k/5k/5k + 3k real）：

| 项 | 值 |
|---|---|
| C1 均值 / sd | **20.43 / 39.49** |
| C1 范围 | 0.087 – 717.3 |
| 单步 PF>3 占比 | **10.3%** |
| C1 与 F5 相关 | 0.850 |
| C1 / F5 均值比 | 3.11 |

C1 是**重尾**成本：少数 `PF>3` 的步被 20 倍放大；因此除了 R²/RMSE，还报
`log1p(C1)` R²、MAE、MAPE，并按“是否触发折点”分组。

## 网络

PER critic：

```text
useq6: state 6 维（u0..u5 /10）  → 6→16→100 ∥ 1→80→50→1，14,073 参数
useq : state 5 维（u1..u5 /10）  → 5→16→100 ∥ 1→80→50→1，14,057 参数
```

- target 同构、`τ=1e-3`；监督 MSE；Adam `1e-3` 余弦到 `1e-4`，30k 步；
- 目标参数化：
  - `logc1 = log(1+C1)`（反变换 `expm1`，保证非负）；
  - `c1 = C1/10`（原始尺度，重尾）。

## 结果

| 状态 / 目标 | test R² | test RMSE | test MAE | test MAPE | log1p R² | real R² / RMSE | C1>15 AUC / F1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| **useq6 / logc1** | 0.960689 | 7.9148 | **2.5424** | **12.43%** | **0.9853** | 0.975346 / 6.5720 | **0.9968 / 0.9449** |
| useq / logc1 | 0.883017 | 13.6534 | 4.8157 | 22.67% | 0.9240 | 0.827071 / 17.4056 | 0.9787 / 0.8993 |
| useq6 / c1（raw） | **0.979611** | **5.7000** | 2.8511 | 26.88% | — | 0.967666 / 7.5264 | 0.9930 / 0.9216 |

基线 `E[C1|u1]`：test **R²=0.2912 / RMSE=33.61**。
⇒ 五步风速把 C1 的 RMSE 从 **33.6 降到 5.7–7.9**；即使只用块内 `u1..u5`
（不含 `u0`），R² 也从 0.29 提到 **0.883**；加 `u0` 后到 **0.961**。

## 行为梯度（重点）

`∂C1/∂a`，test 400 点，δ=0.01，按是否触发 `PF>3` 分组：

| 状态 / 目标 | 梯度 r | 斜率 | 符号 | 余弦 mean | 余弦>0.8 | 余弦<0 |
|---|---:|---:|---:|---:|---:|---:|
| **useq6 / logc1** | **0.9229** | **0.9650** | **0.9515** | **0.885** | **94.2%** | **5.8%** |
| useq / logc1 | 0.8713 | 1.1239 | 0.9337 | 0.855 | 92.8% | 7.2% |
| useq6 / c1（raw） | 0.9270 | 0.7959 | 0.7679 | 0.530 | 76.5% | **23.5%** |

分组细节：

| 组 | useq6/logc1 | useq/logc1 | useq6/raw |
|---|---:|---:|---:|
| smooth（无折点） r | 0.8294 | 0.8216 | 0.5773 |
| smooth 斜率 | 1.3974 | 1.4802 | 1.3515 |
| smooth 余弦 mean | 0.881 | 0.865 | **0.397** |
| smooth 余弦<0 | 5.95% | 6.75% | **30.2%** |
| hinge（触发 PF>3） r | 0.9169 | 0.8635 | 0.9220 |
| hinge 斜率 | 0.9638 | 1.1229 | 0.7944 |
| hinge 余弦 mean | **0.892** | 0.838 | 0.757 |
| hinge 余弦<0 | 5.41% | 8.11% | 12.2% |

关键结论：

1. **`useq6 + logc1` 是梯度最好的方案**：r 0.923、斜率 0.965、符号 0.952、
   余弦 0.885、94.2% 点余弦>0.8；成本也保持 R²=0.961、MAE=2.54、
   log1p R²=0.985。
2. **`u0` 对梯度有明显作用**：去掉 `u0`（严格只用块内 `u1..u5`），
   梯度 r 从 0.923 掉到 0.871、斜率从 0.965 升到 1.124、余弦>0.8 从 94.2% 降到 92.8%。
   C1 第一项 `|P1−P0|` 需要 `u0`；如果 `u0` 是块前量、拿不到，就只能接受 `useq` 的精度。
3. **raw `c1` 目标 RMSE 更好，但梯度明显更差**：RMSE 5.70（比 log 的 7.91 好），
   但梯度斜率 0.796、符号 0.768、余弦仅 0.530、23.5% 反向；smooth 组余弦只有 0.397、
   30.2% 反向。原因是 raw MSE 被重尾 `PF>3` 样本主导，平滑区被欠拟合。
   **做控制/梯度用 `logc1`，只做成本回归可用 raw `c1`。**
4. **hinge 组梯度反而更好**：`PF>3` 时 c1 斜率是 21（而非 1），信号更强；
   `useq6/logc1` 在 hinge 组 r=0.917、余弦=0.892。smooth 组斜率 1.40（高估），
   是主要误差来源。

## 直接拼到初始 obs 的对照

按“初始 obs 已有 `P_G(t−1),u1`，直接把 `u2..u5` 拼进去”的最简方案：

```text
state = [P_G_prev/5, u1/10, u2/10, u3/10, u4/10, u5/10]   # 6 维，无 encoder
target = logc1；其他网络/训练不变
```

| 状态 / 目标 | test R² | test RMSE | test MAE | test MAPE | log1p R² | real RMSE | C1>15 AUC / F1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| obs / logc1（v1 直接拼） | 0.943499 | 9.4887 | 3.2905 | 15.49% | 0.9773 | 10.6757 | 0.9953 / 0.9314 |
| **obs + v6 / logc1** | **0.986637** | **4.6145** | **1.7233** | **8.26%** | **0.9932** | **7.3405** | **0.9986 / 0.9586** |
| useq6 / logc1（v1, u0..u5） | 0.960689 | 7.9148 | 2.5424 | 12.43% | 0.9853 | 6.5720 | 0.9968 / 0.9449 |
| useq / logc1（v1, u1..u5） | 0.883017 | 13.6534 | 4.8157 | 22.67% | 0.9240 | 17.4056 | 0.9787 / 0.8993 |

梯度：

| 状态 / 目标 | r | 斜率 | 符号 | 余弦 mean | >0.8 | <0 |
|---|---:|---:|---:|---:|---:|---:|
| obs / logc1（v1 直接拼） | 0.7813 | 1.1012 | 0.8380 | 0.655 | 82.8% | **17.2%** |
| **obs + v6 / logc1** | **0.9595** | 0.8923 | 0.8869 | 0.745 | 87.2% | 12.8% |
| useq6 / logc1（v1） | 0.9229 | **0.9650** | **0.9515** | **0.885** | **94.2%** | 5.8% |
| useq / logc1（v1） | 0.8713 | 1.1239 | 0.9337 | 0.855 | 92.8% | 7.2% |

分组：

| 组 | v1 obs | **v6 obs** | v1 useq6 |
|---|---:|---:|---:|
| smooth：r / 斜率 / 余弦 / 余弦<0 | 0.847 / 1.467 / 0.587 / 20.6% | 0.917 / 1.013 / 0.635 / **18.3%** | 0.829 / 1.397 / **0.881** / 5.95% |
| hinge：r / 斜率 / 余弦 / 余弦<0 | 0.769 / 1.100 / 0.770 / 11.5% | **0.955 / 0.892 / 0.932** / **3.4%** | 0.917 / 0.964 / 0.892 / 5.41% |

- **v6 直接拼成本最好**：C1 R²=0.9866、RMSE 4.61、MAE 1.72、MAPE 8.26%、
  log1p R²=0.9932、`C1>15` F1=0.9586；明显好于 v1 直接拼（R² 0.9435/RMSE 9.49）
  和 v1 useq6（R² 0.9607/RMSE 7.91）。
- **v6 梯度是混合的**：总 r=0.9595（最高），hinge 组非常好（r 0.955、余弦 0.932、
  仅 3.4% 反向）；但 smooth 组只有余弦 0.635、18.3% 反向，拉低总余弦到 0.745、
  符号 0.887。
- **v1 useq6 的梯度更一致**：余弦 0.885、符号 0.952、仅 5.8% 反向；
  但 hinge 组不如 v6（0.892 vs 0.932），成本也低一截。
- 结论修正：**v1 直接拼不是最优；换成 v6 后直接拼是“成本/折点梯度最好”的方案，
  但平滑区梯度仍弱。** 如果控制主要关心高 C1/折点，选 v6+obs；如果 smooth 区
  的方向一致性也重要，选 v1+useq6，或给 v6 补 `Δu2..Δu5`、`Σu³`、`std/max|Δu|`。

⚠ 这个离线对照里的 `P_G_prev` 仍是 `P(u0,a)`（与当前动作同口径），
不是真实环境的实测 `obs[-1]`；梯度检验固定了 `P_G_prev`，与标签的生成口径不完全一致。
因此它只能作为**初步对照**；要在真实 HSRL 里公平判断，需要用独立的实测
`P_G(t−1)` 重新生成/回放数据。

## 推荐

- **成本 + 高 C1/折点梯度优先**：`v6 + obs + logc1`
  （R² 0.9866 / MAE 1.72 / `C1>15` F1 0.9586 / hinge 余弦 0.932）。
- **smooth 区梯度一致性优先**：`v1 + useq6 + logc1`
  （R² 0.961 / 梯度 r 0.923 / 余弦 0.885 / 仅 5.8% 反向）。
- **只做成本估测**：`v6 + obs + logc1` 最好；`useq6 + c1` raw 次之，
  但 raw 梯度不可用。
- **严格只允许块内 `u1..u5`**：`useq + logc1`（R² 0.883 / 梯度 r 0.871），
  比含 `u0` 差一截；第一项 `|P1−P0|` 的 `u0` 不可省。
- C1 是重尾成本，评估不要只看 RMSE；同时看 `log1p R²`、MAE、以及
  `PF>3` 折点组/平滑组的分组梯度。
